Raritone — Backend

Raritone is a Node.js and Express backend for the Raritone e-commerce platform. It provides product management, authentication, orders, AI-powered virtual try-on integration, and 3D asset management.

Architecture

The backend acts as the central API between the React frontend, MongoDB, ImageKit, and AI services.

3D Asset Management

The backend supports 3D product assets generated by the AI/ML team or supplied as licensed sample assets.

Supported formats:

GLB
GLTF

The 3D asset pipeline is:

AI/ML / Kaggle
      ↓
model.glb
      ↓
POST /api/3d-assets
      ↓
Validation
      ↓
ImageKit Storage
      ↓
MongoDB Metadata
      ↓
PENDING_REVIEW
      ↓
Admin Review
      ↓
APPROVED / REJECTED
      ↓
Product 3D API
      ↓
React 3D Viewer

Large 3D files are not stored directly in MongoDB. The actual file is stored in ImageKit and MongoDB stores the asset URL and metadata.

3D Asset Upload
Endpoint
POST /api/3d-assets

Authentication is required.

The request uses multipart/form-data.

Fields:

asset          → GLB/GLTF file
productId      → Product MongoDB ID
modelVersion   → Optional model version

The backend validates:

Authentication
Product existence

File size

3D Asset Status

The review workflow is:

PENDING_REVIEW
       ↓
   APPROVED

or:

PENDING_REVIEW
       ↓
   REJECTED

Only approved assets are exposed through the public product 3D API.

3D Asset APIs
Upload 3D Asset
POST /api/3d-assets

Uploads and validates a GLB/GLTF asset.

Get 3D Asset
GET /api/3d-assets/:id

Retrieves a specific 3D asset.

Privileged users can access assets under review. Public users can only access approved assets.

Get Product 3D Asset
GET /api/products/:productId/3d

Returns the approved 3D asset associated with a product.

Pending and rejected assets are not returned to customers.

Get All 3D Assets
GET /api/3d-assets

Admin/reviewer endpoint for viewing available 3D assets and their review status.

Review 3D Asset
PUT /api/3d-assets/:id/review

Admin/reviewer can approve or reject an asset.

Approve:

{
  "status": "approved"
}

Reject:

{
  "status": "rejected",
  "reason": "Invalid 3D model"
}

A rejection reason is required when rejecting an asset.

Authorization

Protected routes use JWT authentication.

The backend reads the token from:

Authorization: Bearer <token>

JWT payload contains the authenticated user's:

id
role

Role-based middleware restricts privileged operations.

Customer

Can:

View products
View approved 3D assets
Use virtual try-on
Manage their supported account/order operations

Cannot:

Approve 3D assets
Reject 3D assets
Access pending/rejected assets through the public product API
Vendor

Can:

Create products
Upload 3D assets
Manage assets associated with their authorized products

Cannot:

Manage another vendor's products
Approve or reject 3D assets
Admin / Reviewer

Can:

View 3D assets
View pending assets
Approve assets
Reject assets
3D Asset Validation

Uploaded 3D files are validated before being stored.

Validation includes:

MIME type

Polygon information

The backend uses @gltf-transform/core for 3D asset validation.

The configured upload limit is:

25 MB
Storage

ImageKit is used for storing uploaded files.

The backend stores references to uploaded files rather than storing large binary 3D files directly inside MongoDB.

Example:

 ↓

 ↓

MongoDB

The ThreeDAsset model stores 3D asset metadata and the reference to the stored 3D file.

AI/ML 3D Integration

The AI/ML team can generate 3D assets using Kaggle GPU infrastructure.

The expected package can contain:

RAR-3D-001/
├── model.glb
├── thumbnail.png
├── metadata.json
└── evaluation.json

The backend does not require a GPU.

A real AI/ML-generated model.glb can replace the licensed sample asset without requiring changes to the React 3D viewer or the backend API contract.

Environment Variables

Create a .env file in the backend directory.

Example:

PORT=3000

MONGO_URI=your_mongodb_connection_string

JWT_SECRET=your_jwt_secret

IMAGE_KIT_PRIVATE_KEY=your_imagekit_private_key

FRONTEND_URL=http://localhost:5173

AI_SERVICE_URL=http://127.0.0.1:8000

Never commit .env files or private credentials to GitHub.
